# 营销渠道调研助手

**简体中文** | [English](README.en.md)

输入产品简介、目标客户和目标市场，得到最多 3 个有公开资料依据的推广渠道，以及一封可人工修改的英文合作邮件草稿。结果保存在浏览器中，可随时重新打开。

**技术栈**：Next.js 16（App Router）+ TypeScript + Tailwind CSS 4 + zod；DeepSeek API（聊天模型、Search、Fetch）；数据存于浏览器 localStorage；测试用 vitest。

## 运行

先配置密钥（两种方式共用）：

```bash
cp .env.example .env.local   # Windows: copy .env.example .env.local
# 在 .env.local 中填写 DEEPSEEK_API_KEY
```

**需要自行配置的资源**：一个 DeepSeek API 密钥（聊天模型、Search API、Fetch API 共用，按量计费）。其余变量均可选，见 `.env.example`。

### 方式 1：本地运行（Node.js 20+）

```bash
npm install
npm run dev                  # 打开 http://localhost:3000
```

没有密钥时可用离线模拟数据体验流程（数据为虚构，域名以 `.example` 结尾）：在 `.env.local` 中设置 `DEEPSEEK_API_KEY=mock`、`DEEPSEEK_BASE_URL=http://localhost:8787`，然后先在另一个终端运行 `npm run mock`，再运行 `npm run dev`。

### 方式 2：Docker

需要 Docker Desktop。

```bash
docker compose up -d --build # 打开 http://localhost:3000
docker compose down          # 停止
```

没有密钥时：在 `.env.local` 中设置 `DEEPSEEK_API_KEY=mock`、`DEEPSEEK_BASE_URL=http://mock:8787`，然后运行 `docker compose --profile mock up -d --build`。

测试：`npm test`（61 个用例，无需密钥）。

## 使用

1. 填写产品简介、目标客户、目标市场（可点示例一键填入题目场景），点 **Start research**，约 30–60 秒。
2. 查看渠道卡片：名称、网址、适合原因、原文引用和依据链接。标黄项为未确认信息；不足 3 个时页面会说明原因，并列出被排除的候选。
3. 点 **Write email for this channel** 生成英文草稿，可直接编辑。没有出处的数字标红，客户、效果、合作关系类说法标黄，缺少的信息用 `[Your name]` 这类占位符。工具不发送邮件。
4. 修改输入后再次调研即可得到新结果；**History** 中可重新打开、删除或导出 Markdown。

## 对应题目要求

| 要求 | 实现 |
| --- | --- |
| 可用的网页 | 表单 + 实时进度，修改输入可重新调研 |
| 有依据的渠道推荐 | 网址只取自搜索结果；每条判断附原文引用，由代码在抓取的页面中逐字核对，核对不上标为未确认；依据不足就少推荐 |
| 英文合作介绍草稿 | 只把用户输入和已确认的依据交给模型，生成后由代码检查编造的数字和夸大说法 |
| 可再次查看的结果 | 存于浏览器 localStorage；中断的调研可 Resume |
| 出错时的说明 | 输入缺失、无合格渠道、抓取失败、密钥错误、余额不足、限流、保存失败均有提示和下一步建议 |

## 设计取舍

- **localStorage 而非数据库**：免去部署和配置，评审可以直接运行。代价是数据不能跨浏览器；存储已封装成接口，之后可以替换。
- **宁缺毋滥**：引文必须在页面原文中逐字核对通过才算依据，市场判断也从严。代价是会漏掉一些合适的渠道，但题目要求"有依据"，错误推荐比少推荐代价更高。
- **代码核对而非模型自查**：模型只负责理解和写作，事实核对交给确定性的代码。代价是只能核对"有没有这句话"，语义是否支持结论仍需人工确认。
- **默认关闭模型的思考模式**：`deepseek-flash` 的思考内容计入输出长度上限，开发中曾因此导致 JSON 被截断、初筛失败。关闭后实测初筛约快 5 倍（1.9 秒对 10.7 秒），输出 token 约为七分之一，格式稳定。代价是模型判断可能没那么细；但证据由代码逐字核对，质量不依赖模型想得多深。可用 `DEEPSEEK_THINKING=on` 打开。

## 代码审查

AI 生成的代码按以下四项逐一审查并修复：

- **对照官方文档核对 API**：修正已停用的默认模型名；Fetch 返回 403/404 不再被当成密钥错误而中断整次调研。
- **核实实现与描述是否一致**：事实核对从"只查出处编号"改为核对每个数字；"已确认"标记改为服务端签名，防止伪造。
- **检查需求与错误处理**：写邮件加总时长上限，超时保留初稿；检查点加版本号；修正漏斗统计。
- **为高风险改动补集成测试**：覆盖完整调研、写邮件、从检查点继续、数据被篡改、密钥错误。

## 已知限制

- 目前只支持 DeepSeek，不能直接换用其他 LLM API：聊天模型虽走 OpenAI 兼容接口，但请求带有 DeepSeek 专有参数；搜索和网页抓取用的是 DeepSeek 专有的 Search/Fetch API，其他厂商没有对应接口。如需更换，只需改 `src/lib/deepseek.ts`（聊天部分换成其他 OpenAI 兼容服务，`search()` / `fetchPage()` 换成 Tavily、Brave Search 等），其余代码不受影响。
- 代码只能证明"这句话在页面上"，不能判断它是否支持结论、是否过时，需人工确认。
- 数据只存在当前浏览器，换浏览器、清除站点数据或使用无痕模式会丢失；容量约 5 MB。
- 市场判断较严格（需原文写明或使用目标国家域名），可能漏掉部分 `.com` 网站；拒绝抓取的网站无法推荐。
- 收费情况大多为 “Payment unknown”：只抓取一个页面，收费信息通常在未抓取的投稿或广告页上。
